# 互动性审计·第四部分（人物交互 × 随机性的平衡）

> 生成：2026-08-01 · 依据用户要求：事件/任务要有**人物互动**（不是纯随机抽卡），且人物互动要有**随机性**。
> 前文：`OPTIMIZATION-ROADMAP.md`、`REVIEW-PLAYABILITY.md`、`REVIEW-AUTHENTICITY.md`。

---

## 一、互动现状审计（实据）

### 1.1 NPC 阵容：覆盖全阶段，但深度不均
8 个有名字的 NPC：
- 本科：室友张宁、陈师兄、李老师（带教）、王辅导员
- 实习：林主治（带教）
- 实习/规培：刘护士长
- 规培：赵师姐（高年资规培）
- 硕博/职业：周教授（导师）

### 1.2 好感度系统的真实使用率（关键缺口）
- `events_npc_affinity.ts` 已消费 `trust_*` / `distant_*` flag：五个核心 NPC 均有信任门控事件，
  室友与师兄另有疏远修复分支；本科带教与辅导员也有双向门控。
- 行走场景对话与随机事件卡现在都能反映关系，但主治、护士长、师姐仍缺疏远向随机事件，
  好感度对结局和大多数任务也尚无直接影响。

### 1.3 链式事件：36 条 `nextEventId`——交互链存在
- 保研链、国奖链、学术不端链、导师链等分支互动已建，是互动性的亮点。

### 1.4 随机性现状
- 事件抽取：`weightedRandom` + 手写优先（运气加成）——事件"何时遇到"是随机的 ✓
- 但**人物事件与随机事件混杂**：抽到"主任批评"还是"主任赏识"纯看权重，与你和主任的关系无关——互动缺位。

---

## 二、用户意图的平衡点（人物互动 × 随机性）

> 理想形态：**随机性 = "今天会遇到谁/遇到什么事"；互动性 = "遇到之后，关系决定结果"**。
> 当前只有前者，缺后者。

---

## 三、任务清单（互动性优先）

### P0 · 让随机事件消费 NPC 好感度（最高价值）
- [x] 为 roommate/senior/headnurse/fellow/attending 增加**好感度门控事件**：
  - 信任（aff≥70）→ 解锁隐藏选项/更好结果（如室友信任→"他帮你顶了次查寝"，护士长信任→"出事时帮你说话"）
  - 疏远（aff≤25）→ 当前已覆盖室友/师兄；主治、护士长、师姐的疏远向仍待补
  - 选项可用性用 `requireFlag: trust_xxx / distant_xxx`（好感度系统已自动打这两个 flag——见 npc.ts TRUST_AT/DISTANT_AT）
- [x] 室友/师兄关系已能改变后续随机事件结果，并有自动化门控回归

### P1 · 好感度跨阶段延续
- [x] 本科关系通过信任 flag 跨阶段回响：
  - 室友在规培以老同学身份重逢，陈师兄在职业期以同行身份重逢
  - 导师周教授好感度已跨 master→career ✓，可作为范式

### P1 · 任务清单互动化
- [ ] QuestLog 当前是静态文本（"去地点领一件事"）。改为：
  - 任务高亮指向具体 NPC/地点（地图打点或文字指引）
  - 任务完成有反馈（NPC 道谢、图鉴/徽章联动）
  - 任务与好感度挂钩（"和室友聊聊"→ 完成后室友好感+）

### P2 · 更多链式互动事件
- [ ] 在 36 条链基础上，增加"人物关系链"：与某个 NPC 的多阶段互动（初识→误会→和解→信任），而非单次事件

### P2 · 随机性与确定性分层
- [ ] 明确分层：**人生节点（诉讼/亚专科/选校）确定性触发**（已做）+ **人物互动事件按好感度/随机** + **日常填充纯随机**
- [ ] 写一份"事件分层规范"文档，指导后续加事件（哪类事件走哪层）
